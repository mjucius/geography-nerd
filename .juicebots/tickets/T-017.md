# T-017: Trickiness in km, level bands, enough pairs, no repeats

## Acceptance
- Each pair is scored by the asked-axis gap and the other-axis gap in km, from the same function the reveal uses; the asked axis is still the one with the smaller gap (brief 4).
- The ratio gate in `quizService.ts` is gone; the level table has the km bands.
- A test enforces that each level from 2 to 10 is at least as hard as the one before on familiarity and on trickiness, and strictly harder on at least one (brief 5).
- Every level has at least 200 valid pairs, checked by a test on the real data, and no pair appears twice in one quiz (brief 7).
- Level 1 uses clear gaps; level 10 includes pairs close on the asked axis and far apart on the other (brief 6).
- `npm test` and `npm run lint` pass.

## Plan
Files: `web/src/services/levels.ts` (three band columns), `web/src/services/cityDataService.ts` (memoize each level's pool so the same array comes back every call), `web/src/services/quizService.ts` (pair enumeration replaces the ratio gate and random search), tests `web/src/services/__tests__/levels.test.ts` (new) and `quizService.test.ts` (rewritten).
Approach: each `LEVELS` row gains `askedMin`, `askedMax`, `otherMin` in km. For a pair, `getDistanceInfo` (the function the reveal uses) gives the north-south and east-west gaps in km; the asked gap is the smaller, the other gap the larger. A pair is valid for a level when both cities are in the level's pool, `asked > 0` (an exactly zero asked gap means the cities share that axis, which the binary answer cannot express, for example Medan and Buenaventura on the same latitude), `askedMin <= asked <= askedMax` and `other >= otherMin`. Starting table, checked against the real data (valid pairs per level in brackets): L1 1500+ [454], L2 1000+ [1108], L3 700+ [2990], L4 400-2000 [3303], L5 250-1000 [4429], L6 150-600 with other 1000+ [4960], L7 100-400 other 1500+ [6408], L8 50-250 other 2000+ [7051], L9 0-150 other 3000+ [7064], L10 0-100 other 3000+ [7325, one pair excluded by the zero rule]. `validPairs(pool, level)` enumerates the pairs once per pool array (WeakMap cache; level 10 is 499,500 distance checks, run once) and stores index pairs. `generateQuestions(cities, level)` keeps its signature and `useQuiz` is untouched: it picks 8 random pairs from the current level's list and 2 from the next level's, without replacement, with one shared set of used pair keys so no pair repeats across the two tiers either, and puts the cities in random order within a pair. The question axis is chosen in km: latitudinal when the north-south gap is smaller than the east-west gap (a tie asks east-west, as before); the answer logic is unchanged. Deleted: `getDistanceRatio`, `isValidRatioForTier`, the 100-attempt loop and the `attempts === maxAttempts` stopgap, `enforceRatio`, and the top-up loop (every level has hundreds of pairs, which a test enforces).
Tests: `levels.test.ts` reads the real table and cities: 10 levels; for levels 2 to 10 pool, `askedMin`, `askedMax` and `otherMin` are each at least as hard as the previous level (pool >=, askedMin <=, askedMax <=, otherMin >=) and at least one of the four differs; every level has at least 200 valid pairs; level 1 has `askedMin` >= 1,000 km (a clear gap) and a pool of the most familiar cities; level 10 has a pool of all cities and valid pairs with asked <= 100 km and other >= 3,000 km. `quizService.test.ts`: over 50 quizzes per level, no pair repeats in a quiz, every question's pair is inside its own tier's pool and band (checked with `getDistanceInfo`), each quiz has 8 current + 2 next (10 at level 10), and `question.type` agrees with the smaller km gap; a regression test that Medan and Buenaventura (same latitude, about 19,500 km apart east-west) is not in level 10's valid pairs while the same pair with a 0.001 degree latitude offset is; and a tie test with two cities whose north-south and east-west km gaps are equal and nonzero (built from `getDistanceInfo` on the equator, so the cos factor is 1), which asks east-west.
Prove tests can fail on a copy outside the repo: loosen L5's `askedMax` above L4's (monotonic test red); drop the `otherMin` of level 10 to 0 so a band test or the ends test goes red; shrink L1's band until under 200 pairs (pair-count test red); remove the used-pair set (no-repeat test red); compare degrees instead of km for the axis (type-agreement test red on a pair where the two orders differ, which I will include); drop the pool check in `validPairs` (tier-pool test red); drop the `asked > 0` rule (the Medan and Buenaventura test red).
Run `npm test`, `npm run lint`, `npx tsc -b` and `npm run build:web` in the foreground and read exit status. Time the first quiz at level 10 (pair enumeration cost) and report it.

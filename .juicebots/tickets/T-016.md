# T-016: Level table with pools by familiarity, Wikidata credit

## Acceptance
- One level table replaces the population and capital filters in `cityDataService.ts`. Level 1 uses only the most familiar cities, and each later level's pool is at least as big as the one before; level 10 uses all ~1,000 (brief 3, 5, 6).
- `is_capital`, the hand-written capitals list and the capital filters are gone from the data, types, generator script and tests (brief 3).
- A test enforces that the pools never shrink from level 2 to 10 and grow at least once.
- Wikidata (CC0) is credited in `ATTRIBUTION.md` and in the in-app Credits, with a test on the Credits list (brief 2).
- 10 levels, same names, 8/10 unlocks the next, 8 + 2 preview questions, level resets each visit, `PRIVACY.md` unchanged (brief 8).
- `npm test` and `npm run lint` pass.

## Plan
Files: new `web/src/services/levels.ts`, `web/src/services/cityDataService.ts`, `web/src/services/quizService.ts` (drop `cities.slice(0, 100)` in `generateQuestions`; the ratio gate stays until T-017; stopgap below), new `web/src/services/__tests__/quizService.test.ts`, `web/src/types/index.ts` and `web/src/data/localCities.ts` (remove `is_capital`), `scripts/generate-local-cities.mjs` (drop the capitals set and the 7th column), `web/src/data/cities.json` (regenerated, 6 columns), `data/cities-import.sql` (delete the `UPDATE cities SET is_capital` block at the end), `scripts/import-cities.mjs` (delete `CAPITAL_CITY_KEYS` and the `is_capital` column), `web/src/components/AboutModal.tsx` (Wikidata credit), `ATTRIBUTION.md`, tests.
Approach: `levels.ts` exports `LEVELS`, a table with one row per level 1 to 10, `{ pool }`: the number of most familiar cities that level draws from. Starting values 40, 60, 90, 130, 190, 270, 400, 560, 760, 1000 (T-017 adds the km band columns to the same rows). `getCitiesByDifficulty(level)` ranks `LOCAL_CITIES` by sitelinks (ties by population, then id) once, and returns the first `LEVELS[level - 1].pool`; it no longer sorts by population or caps at 100. Level 10 returns all 1,000, level 1 the 40 best known. The population and capital `switch` is deleted. `generateQuestions` stops slicing to 100 and uses the pool it is given; preview questions already call `getCitiesByDifficulty(next)`. With bigger pools the old ratio gate gets rare at the hard levels (about 2% of level-9 pairs pass), so a question can use up its 100 attempts. Today a failed question is dropped and the quiz tops up from current-level cities, which would break 8 current + 2 preview. Fix in `generateSingleQuestion`: when the last attempt still fails the gate, accept that pair anyway (`attempts === maxAttempts`), so the question keeps its own tier and pool; the top-up loop in `generateQuestions` then never fires. This is a stopgap, marked with a comment; T-017 replaces random search by enumeration of valid pairs. Capitals: removed from the types, loader, generator and `cities.json` columns, the SQL's trailing UPDATE, and the import script, so nothing in the repo knows what a capital is. Credits: a list item "Familiarity data: Wikidata (CC0)" linking https://www.wikidata.org/ in `AboutModal.tsx` (same markup as the GeoNames item), and a "Familiarity" section in `ATTRIBUTION.md` naming Wikidata sitelink counts, CC0, and the `fetch:sitelinks` script.
Tests: replace the old capital and population tests in `cityDataService.test.ts` and delete `frozenLevelIds.ts` (its job, covering the temporary slice, ends here). New tests: each level returns exactly `LEVELS[level-1].pool` cities, all ranked by sitelinks, so no excluded city has more sitelinks than an included one; pools never shrink from level 2 to 10 and grow at least once; level 10 returns all of `LOCAL_CITIES`; each level's cities are a subset of the next level's; level 1 is strictly the most familiar (every city in it has at least as many sitelinks as any city outside it). A data test that no city has `is_capital`, `cities.json` rows have 6 columns, and the SQL no longer mentions `is_capital`. Deterministic `generateQuestions` tests in a new `quizService.test.ts` that force retry exhaustion: `vi.mock` `getCitiesByDifficulty` to return two cities on the same latitude (ratio is Infinity, which fails the gates of levels 5, 8 and 9), pass two such cities as the current pool, and assert for levels 5, 8 and 9 exactly 8 questions with `difficultyLevel` equal to the level and 2 with the next level, every question's cities in its own tier's pool, and 10 questions at level 10 (all level 10). A second test on the real data for levels 1 to 9 over 20 runs each asserts 8 + 2 by `difficultyLevel`, and that each question's cities are in its own tier's pool (`getCitiesByDifficulty(question.difficultyLevel)`). `AboutModal.test.tsx`: the Credits list shows Wikidata with a link to wikidata.org and CC0. `ATTRIBUTION.md` is not tested.
Prove tests can fail on a copy outside the repo: rank by population instead of sitelinks (ranking test red); make pools equal for all levels (grow-at-least-once test red); shrink one level's pool below the previous (monotonic test red); remove the `attempts === maxAttempts` acceptance (the forced-exhaustion tests go red); remove the Wikidata item from the modal (credits test red); put `is_capital` back in the generator (no-capital data test red). Also run `generateQuestions` at every level 200 times in a throwaway script and count how often the stopgap accepts a gate-failing pair, to report it.
Run `npm test`, `npm run lint`, `npx tsc -b` and `npm run build:web` in the foreground and read exit status; `npm run generate:local-cities` and check it reproduces the committed `cities.json`.
Note for later: `scripts/import-cities.mjs` writes SQL with a different column list than the committed `data/cities-import.sql` (which `generate-local-cities.mjs` parses). I am not fixing that here (out of scope); I will mention it to team-lead.

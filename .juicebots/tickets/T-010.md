# T-010: Route line takes the short way across the date line

## Acceptance
- For Auckland and Honolulu the line crosses the Pacific over the date line, not the whole map; both pins and the full line are visible in the first view, on the reveal and in the results map (brief 18).
- Map, answer key and distance text agree on east/west: the map shows city1 on the side the text says (19). Answer key and distance logic are not changed.
- Ordinary pairs (no date line crossing) render as before.
- Quiz behaviour unchanged; `npm test` passes.

## Plan
Files: `web/src/components/MapView.tsx`, `web/src/components/__tests__/MapView.test.tsx`. `distance.ts` and the quiz are untouched.

Approach: export a pure `routePositions(city1, city2)` from `MapView.tsx` returning `[p1, p2]` as `[lat, lon]`. p1 is city1 as is. p2's longitude is `city1.longitude - wrapLongitudeDiff(city1.longitude, city2.longitude)`, so |p2 lon - p1 lon| <= 180 and city1 is east of city2 exactly when `getDistanceInfo` says East (same wrap helper, same sign). `MapView` uses these for both markers, the polyline and `LatLngBounds`. Leaflet draws longitudes past 180 on the repeated world copy, so tiles and pins show. Ordinary pairs: the wrapped diff equals the plain diff, so p2 lon is unchanged (float rounding aside; test uses toBeCloseTo).

Tests (`MapView.test.tsx`, pure helper, no Leaflet needed):
- Auckland/Honolulu: lon span <= 180 (p2 lon about 202.2).
- Tokyo/Sydney (ordinary): positions equal the inputs.
- East/west agreement: for Auckland/Honolulu and a reverse pair, sign of (p1 lon - p2 lon) matches `getDistanceInfo(city1, city2).ew.direction` (East when positive).
- Existing render tests stay green.
Prove each fails: on a copy outside the repo, make `routePositions` return raw longitudes; the span and agreement tests should go red.

Browser check (headless Chrome via playwright-core, outside the repo): Auckland/Honolulu on reveal and results at 390px wide, confirm both pins and the whole line sit in the first view. Result noted below.

# T-013: Same longitude / same latitude

## Acceptance
- Exactly the same longitude (0 deg gap the short way): the east-west line reads "Same longitude", no direction, no km or mi. Exactly the same latitude: the north-south line reads "Same latitude" the same way. On both the answer reveal and the results screen (brief 23).
- Only an exact 0 deg gap counts; a non-zero gap that rounds to 0 km keeps its direction ("East by 0 km / 0 mi"); every other pair shows both lines as before (24).
- Tests cover a same-longitude pair, a same-latitude pair and a tiny non-zero gap.
- `npm test` and `npm run lint` pass.

## Plan
Files: `web/src/services/distance.ts`, `web/src/components/QuestionCard.tsx`, `web/src/components/ScoreScreen.tsx`, tests in `web/src/services/__tests__/distance.test.ts` and the QuestionCard and ScoreScreen tests.
Approach: `offset()` gains `same: degrees === 0` (exact; the longitude gap is already wrapped, so two cities 360 apart in raw longitude count as the same). New exported `formatOffset(offset, sameLabel)` in `distance.ts`: `sameLabel` if `same`, else `${direction} by ${formatDistance(offset)}`. Both components use it for the two lines (`'Same latitude'` for ns, `'Same longitude'` for ew), so one rule serves both screens.
Tests: distance tests for same longitude, same latitude, tiny gap (0.0001 deg: `same` false, direction kept, formats as "East by 0 km / 0 mi"), normal pair; one QuestionCard and one ScoreScreen test with a same-longitude pair showing "Same longitude" and no "by 0 km". Prove they fail on a copy outside the repo: `=== 0` to `< 1` (tiny-gap test red); components bypassing formatOffset (component tests red).
Run `npm test` and `npm run lint` in the foreground and read exit status.

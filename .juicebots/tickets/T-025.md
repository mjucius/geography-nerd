# T-025: Re-running import-cities produces a file the generator cannot read

## Acceptance
- `npm run import-cities` writes `data/cities-import.sql` in the row format that `generate-local-cities.mjs` (and `fetch-sitelinks.mjs`) parse: `('Name', 'CC', population, latitude, longitude)` (CEO request, issue found while building T-016).
- Writer and reader live in one shared module, so they cannot drift apart again.
- A test shows the round trip: the committed SQL parsed, written by the import's writer and run through the generator gives a `cities.json` identical to the committed one.
- `npm test` and `npm run lint` pass.

## Plan
Problem (checked): `generateSQL` in `scripts/import-cities.mjs` writes `INSERT INTO cities (name, country, country_code, population, latitude, longitude, region)` with rows `('Name', 'CC', 'CC', pop, lat, lon, 'Region')`, while `data/cities-import.sql` and the generator's regex use `('Name', 'CC', pop, lat, lon)`. The regex finds zero rows in the writer's output, so the generator would crash (it would see an empty city list), and the same regex is copied in `fetch-sitelinks.mjs` and in four tests.
Approach: new `scripts/cities-sql.mjs` exports `formatCitiesSql(cities)` (cities as `{ name, countryCode, population, latitude, longitude }`; batches of 100 rows; `INSERT INTO cities (name, country, population, latitude, longitude) VALUES`, rows `('Name', 'CC', pop, lat, lon)`, quotes doubled in names, wrapped in BEGIN/COMMIT) and `parseCitiesSql(text)` (the one regex, returning the same shape). `import-cities.mjs` imports `formatCitiesSql` and drops its own `generateSQL`; its `getRegion` stays because city selection uses it. `generate-local-cities.mjs` and `fetch-sitelinks.mjs` import `parseCitiesSql` instead of their own copies. `import-cities.mjs` also takes an optional output path as its first argument (default `data/cities-import.sql`) so it can be checked without touching the repo. The committed SQL is not changed (it still has its trailing UPDATE lines, which the regex ignores and the writer no longer emits).
Tests (`web/src/services/__tests__/citiesSql.test.ts`, node environment): (1) `parseCitiesSql` of the committed SQL gives 1000 rows with the expected first row (Shanghai); (2) `formatCitiesSql(parse(committed))` parses back to the same rows, including names with a quote or an accent (a synthetic row set adds `O'Fallon`, `São Paulo`); (3) a batch boundary: 250 synthetic rows come back as 250; (4) end to end: copy `data/` into a temp directory, replace `cities-import.sql` by the writer's output, run `node scripts/generate-local-cities.mjs` there and compare its `cities.json` with the committed file byte for byte; (5) the old writer's row shape (`('X', 'CC', 'CC', 1, 2, 3, 'Asia')`) parses to zero rows, a note on why the format matters, kept as a guard that the shared parser stays strict.
Real run (format-only smoke check, explicit about its setup): in a temp directory `$TMP` I run `node <repo>/scripts/import-cities.mjs $TMP/data/cities-import.sql` (cwd `$TMP`, downloads GeoNames cities1000.zip once). The generator also needs `data/countries.sql` (copied from the repo), `data/city-sitelinks.json` and `data/excluded-cities.json`, and writes `web/src/data/cities.json`, all relative to its cwd. A fresh GeoNames selection will not match the committed sitelink metadata, so for the smoke check only I write temporary synthetic sitelink counts for exactly the imported rows (`sitelinks: 1` for every key the parser returns) and an empty `{}` exclusions file into `$TMP/data/`, create `$TMP/web/src/data/`, and run `node <repo>/scripts/generate-local-cities.mjs` with cwd `$TMP`. I check that it exits 0 and that `$TMP/web/src/data/cities.json` has the same number of rows as the import wrote (1000). Nothing from `$TMP` is committed and the repo's data files are untouched; the real data keeps being checked by the committed-metadata byte-for-byte round-trip test (4 above).
Prove tests can fail on a copy outside the repo: put the old writer shape back into `formatCitiesSql` (round-trip and end-to-end tests red); break quote escaping (the `O'Fallon` test red); change the parser regex to the 7-column shape (committed-SQL test red).
Run `npm test`, `npm run lint`, `npx tsc -b`, `npm run build:web` in the foreground and read exit status; `generate:local-cities` leaves `cities.json` unchanged.

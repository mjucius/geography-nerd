# T-019: Same place appears twice in the city data

## Bug
Four places are in `web/src/data/cities.json` twice under different names, a few km apart, with the same Wikidata QID and sitelink count in `data/city-sitelinks.json`:
- Benito Juarez|MX and Benito Juárez|MX (Q2356998)
- Fuencarral|ES and Fuencarral-El Pardo|ES (Q656196)
- Jaboatão|BR and Jaboatão dos Guararapes|BR (Q271393)
- Lexington|US and Lexington-Fayette|US (Q49241)

Steps: group `data/city-sitelinks.json` by `qid`; four QIDs have two keys.

Expected: each real place is one city, so a quiz never asks "is Lexington north of Lexington-Fayette", and the pools spend their slots on distinct places.
Actual: both rows ship, rank next to each other in the familiarity ladder (same count), and are pairable in a question (at levels 1 to 9 a pair this close is accepted whenever the ratio rule passes).

Brief 1 says "every city in `data/cities-import.sql`"; dev to remove or merge the duplicate rows (keeping the count test honest) or ask pm if the 1,000 must stay at 1,000.

## Acceptance
- A test shows no two cities in `LOCAL_CITIES` share a Wikidata QID.
- A test shows (per pm's Decision 10) no shipped row for the Benito Juarez / Benito Juárez pair or the Fuencarral / Fuencarral-El Pardo pair (both are sub-city entries), and exactly one shipped row each for Lexington and Jaboatão dos Guararapes (Lexington-Fayette and Jaboatão are gone).
- `npm test` and `npm run lint` pass.

## Plan
Decided with pm (Decision 10 in the brief): the duplicates ship once, removed through `data/excluded-cities.json`, not by editing the SQL or the sitelinks file. Benito Juárez and Benito Juarez (a Mexico City alcaldía) and Fuencarral and Fuencarral-El Pardo (a Madrid district) both go as sub-city entries; Jaboatão and Lexington-Fayette go as duplicates of Jaboatão dos Guararapes and Lexington. So 6 rows leave and the count is 994.
Files: new `data/excluded-cities.json`, `scripts/generate-local-cities.mjs`, regenerated `web/src/data/cities.json`, tests `web/src/services/__tests__/cityDataService.test.ts` and `citySitelinks.test.ts`, docs `CONTRIBUTING.md` and `README.md` (one line on the file).
Approach: `excluded-cities.json` is `{ "Name|CC": "reason" }`, here `"Benito Juárez|MX": "part of Mexico City"`, `"Benito Juarez|MX": "part of Mexico City"`, `"Fuencarral|ES": "part of Madrid"`, `"Fuencarral-El Pardo|ES": "part of Madrid"`, `"Jaboatão|BR": "duplicate of Jaboatão dos Guararapes"`, `"Lexington-Fayette|US": "duplicate of Lexington"`. The generator reads it, skips those keys when building rows, assigns ids after the skip (so ids stay 1..n), and throws if an excluded key is not a row of the SQL (a typo would otherwise silently do nothing). `city-sitelinks.json` stays covering every SQL row, so the T-014 test (keys equal SQL keys) stays as is, apart from its bound.
Tests: (cityDataService.test.ts) the shipped count equals the SQL row count minus the excluded keys, and ids are unique and 1..n; no two shipped cities share a Wikidata QID (shipped city keys mapped through `city-sitelinks.json`); Lexington and Jaboatão dos Guararapes are each present once; Benito Juárez, Benito Juarez, Fuencarral, Fuencarral-El Pardo, Jaboatão and Lexington-Fayette are absent; every excluded key is an SQL row and has a non-empty reason; the existing sitelink and Paris tests stay. The levels tests (200 valid pairs, level 10 draws from every shipped city) run against the new data unchanged. One assertion changes: the `getCitiesByDifficulty` test expecting `LEVELS[level - 1].pool` cities per level becomes `Math.min(LEVELS[level - 1].pool, LOCAL_CITIES.length)`, because level 10's pool of 1000 now exceeds the 994 shipped cities; the separate assertion that level 10 returns every shipped city stays. The 1,000 in `levels.ts` stays as the pool cap (T-022 will lower the count again).
Prove tests can fail on a copy outside the repo: empty `excluded-cities.json` and regenerate (QID, absent and count tests red); drop only Lexington-Fayette from the file (QID and Lexington tests red); add a made-up key to the file (generator throws, and the stale-key test is red).
Run `npm test`, `npm run lint`, `npx tsc -b`, `npm run build:web` and check `npm run generate:local-cities` is reproducible, in the foreground.

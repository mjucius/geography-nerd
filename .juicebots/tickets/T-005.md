# T-005: Restyle answer reveal and map

## Acceptance
- Reveal shows the result, the distance and the map; pins and route line use palette colours (no default blue Leaflet pins, no unpkg icon requests); tile pane is muted to match the palette.
- Distances show km and miles; degrees are gone.
- Remove the unpkg leaflet.css link from web/index.html (MapView already imports leaflet.css), so tiles are the only third-party request.
- Only the Next/Complete button advances; clicking elsewhere in the panel does nothing (test).
- Quiz behaviour unchanged; `npm test` passes.

- Cards are never nested more than one level deep on this screen.

## Review notes

### plan review, round 1: changes
- Bug carried into the new helper: `quizService.ts:146-150` wraps `lonDiff` into [-180, 180] and decides East/West from the wrapped value (line 179). The reveal's distance maths, which the plan copies "as today", uses the raw `city1.longitude > city2.longitude` and the raw `abs` difference. For a pair across the dateline (e.g. Auckland 174.8 vs Honolulu -157.9), the quiz says the correct answer is West, but the reveal would print "East by 37,000 km" (332.7 deg x 111.32). Now that degrees are gone and km is the headline, this shows up badly. In `getDistanceInfo`, wrap `lonDiff` the same way, take the direction from the sign of the wrapped value, and add a dateline pair to `distance.test.ts` that asserts the direction matches `quizService` and the km is under 20,000.
- Otherwise good: the shared helper (T-006 reuses it), Next-only advance with a test that a panel click does nothing, the flat section with no nested card, divIcon pins (no unpkg), the unpkg leaflet.css removed and the muted tile pane.
- Nit, non-blocking: E-W km uses 111.32 km per degree at every latitude, so it overstates near the poles (x cos(lat) would fix it). That's a product call; leave it unless pm wants it.
- Nit, non-blocking: format with a fixed locale (`toLocaleString('en-US')`) so tests don't depend on the machine's locale.
- Nit, non-blocking: `.route-line`/`.map-pin` read `var(--color-*)` in plain CSS. Confirm in `dist` that the variables are emitted (Tailwind v4 can drop unused theme vars).
